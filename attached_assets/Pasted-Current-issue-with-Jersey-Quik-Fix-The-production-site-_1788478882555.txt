Current issue with Jersey Quik Fix
The production site is:
https://jerseyquikfix.com
https://www.jerseyquikfix.com
Both domains are currently connected directly to the jersey-quik-fix Cloudflare Worker and are proxied through Cloudflare.
On at least one Comcast Business network with SecurityEdge enabled, visiting the site displays:
“Malware and Phishing — This site is blocked because it is a known security threat.”
If SecurityEdge is disabled on that network, the website loads normally.
However, Comcast’s own Advanced Security Website Checker currently says:
“No Advanced Security block related to the reported website / No unsafe content found.”
So there is a discrepancy between the live SecurityEdge behavior and Comcast’s public checker.
I then checked the domain through multiple security vendors. The overwhelming majority classify it as clean, including Google Safe Browsing, Bitdefender, Kaspersky, ESET, Sucuri, OpenPhish, PhishTank, Webroot, etc.
But these vendors currently flag it:
Sophos — Malware
Fortinet — Malware
alphaMountain.ai — Suspicious
VirusTotal currently shows approximately 3/91 security vendors detecting the site.
I also ran the website directly through SophosLabs Intelix. Sophos currently reports:
Verdict: Malicious
Risk level: High
Category: Spyware and malware
HTTP response: 200 OK
Certificate: valid
Sophos machine-learning analysis: Likely Clean
So Sophos’s reputation/category system says the domain is malicious even though its own machine-learning content analysis says it is likely clean.
Please investigate why these security/reputation systems could be flagging the production site.
